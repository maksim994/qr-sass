## Политика iframe — согласовано с Максимом

21.10 Максим выбрал: «Разрешить встраивание только своему сайту и доменам Метрики — сохранить Вебвизор».

На публичных страницах CSP содержит `'self'` и явный список официальных HTTPS-источников Яндекс Метрики; Webvisor — `https://webvisor.com` и `https://*.webvisor.com`. Общего `*.yandex.ru` и разрешения `http:` нет. `X-Frame-Options: SAMEORIGIN` сохранён как защита для старых клиентов: современные Chrome/WebKit применяют CSP `frame-ancestors` вместо него. Приватные маршруты кабинета, админки, API, входа/регистрации, предпросмотра и пользовательских QR имеют строгую CSP только `'self'`.

Официальные источники Яндекса:
- [Показ данных в iframe](https://yandex.ru/support/metrica/ru/behavior/link-map#about-iframe): исключения для Метрики и Webvisor.
- [CSP, адреса для frame-ancestors](https://yandex.ru/support/metrica/ru/code/install-counter-csp): актуальный список доменов.

Проверка браузерной политики: `scripts/verify-tz10-frames.mjs` берёт фактические заголовки локального приложения и проверяет их в изолированных HTTPS-iframe. Все внешние адреса перехватываются Playwright; запросов на production/Яндекс нет. Проверяются свой origin, Метрика, поддомен Webvisor (разрешены), посторонний и похожий на Яндекс домен, HTTP и встраивание входа из Метрики (запрещены). **14/14 проверок в Chrome и WebKit пройдены**; результаты в `frame-acceptance.json`.

Настоящая запись Вебвизора в аккаунте Метрики здесь не открывалась. Её просмотр после релиза остаётся частью ручной приёмки; проверка CSP не подменяет эту проверку.

## Как проверить локально

Запущенный сервер: `http://127.0.0.1:3010/contacts` (если локальный процесс ещё работает).

1. Открыть контакты на компьютере и телефоне, проверить Telegram/почту/телефон и ссылки на оферту/политику.
2. На главной в «Типы QR» выбрать «Текст»: откроется ввод без нового URL. Для Wi-Fi и визитки проверить переход на лендинг.
3. В бесплатном тестовом workspace с ≥3 динамическими кодами проверить смену назначения третьего: переход на тарифы в UI, 403 в API. Удалить первый — следующий становится доступен. Напечатанная ссылка третьего продолжает работать.
4. В редакторе статьи проверить теги и связанные ID. Для тестовой склейки заранее перенести содержимое, выбрать целевую статью и подтвердить; 301 и исключение из sitemap включаются одновременно.
5. После релиза проверить Вебвизор/карты Метрики и Яндекс.Вебмастер в настоящем аккаунте.

Повторный запуск HTTP-проверки (создаёт только локальные синтетические записи):

```sh
DATABASE_URL=postgresql://mvmolkov@127.0.0.1:5432/qr_tz10 \
JWT_SECRET=local-tz10-verification-secret-with-32-characters \
APP_URL=http://127.0.0.1:3010 \
node --experimental-strip-types --import ./scripts/register-src-alias.mjs scripts/verify-tz10-stage1.mjs
```

Browser-проверка использует Playwright из `PLAYWRIGHT_MODULE` либо установленный модуль `playwright`. Файл `/tmp/tz10-fixture.json` с **локальной** сессией создаёт HTTP-проверка; он не включён в Git.
