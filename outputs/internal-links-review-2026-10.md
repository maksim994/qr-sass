## Что подтверждено и что ожидает исходники

- В публичном HTML 44 статей нет ссылок на четыре статических источника из `BLOG_REDIRECTS`.
- Таблица `blogRedirect`, `content` непубличных статей и реальные `relatedArticleIds` недоступны. Полная проверка данных не заявляется выполненной.
- Без исходного `content` нельзя подготовить гарантированно побайтовую замену в HTML/Markdown. Все фрагменты плана честно помечены как публичный HTML. Ключ API не предоставлен; SSH-доступ не установлен; доступная локальная база пуста. Production API не вызывался и новый ключ не создавался.
- Перед применением получить свежий редакционный snapshot, сопоставить фрагменты с `content`, объединить изменения по статье, проверить версию, сохранить ревизию и получить одобрение Максима. Не переносить публичный HTML в поле `content` целиком.
- В статье об отзывах нет отдельного раздела о 2ГИС. Предложена ссылка из существующего шага о выборе площадок без нового раздела и фактических обещаний.
- В таблице размеров уже есть наружная реклама: баннер у входа и вывеска издалека. Строки специально для полотна 3 × 2,5 м нет; текст таблицы не правился.

## Скрипты

Основной dry-run получает **локальный snapshot**, разрешает слаги в настоящие ID, выводит diff `relatedArticleIds`, сохраняет прежние ручные назначения и сообщает о недоступных, неопубликованных, перенаправленных статьях и неизвестных ID. Сами relatedArticleIds не пишутся. Отчёт редиректов проверяет HTML, Markdown, reference links и ручные relatedArticleIds против обоих источников редиректов.

```sh
node --experimental-strip-types scripts/internal-links-dry-run.mjs --snapshot /tmp/editorial-snapshot.json
```

Формат snapshot: объект с `posts` и `redirects`. В каждой статье обязательны `id`, `slug`, `content`, `format`, `relatedArticleIds`; для предложений related также нужен `publishedAt`. В каждом редиректе — `source` и `target`. `redirects: []` разрешён только при действительно пустой таблице.

Опциональный экспортёр использует `getDb()`, один согласованный снимок `RepeatableRead`, `SET TRANSACTION READ ONLY` и выбор только редакционных полей. Сохранение — в новый приватный файл с правами `0600`. Против production в этой задаче не запускался.

```sh
node --env-file=/secure/database.env --experimental-strip-types --import ./scripts/register-src-alias.mjs scripts/export-internal-links-snapshot.ts /tmp/editorial-snapshot.json
```

В dry-run нет подключения к БД, сетевых запросов или режима `--apply`. Неизвестные флаги отклоняются. В экспортёре нет изменения статей, ревизий или редиректов. Приватные snapshot с черновиками не коммитить.

## Проверка

Локальные проверки: `npm test`, `npm run lint`, `npx tsc --noEmit`; дополнительно HTTP-проверка девяти затронутых лендингов с проверкой HTTP 200, новых ссылок, анкоров и отсутствия дубликатов. Подробности — `internal-links-http-2026-10.json`.

Новые тесты проверяют: оба источника редиректов, Markdown reference links, исключение внешних ссылок и примеров кода, разрешение ID и сохранение ручных назначений, идемпотентность, блокировку отсутствующих и непубличных целей, отказ от `--apply`, общий лимит ссылок. Проверки данных выполняются на синтетических fixture; это не подменяет ожидающий snapshot-аудит production.

Локальный итог: 311 тестов прошли, ESLint без ошибок и предупреждений, TypeScript без ошибок, 9/9 HTTP-проверок прошли. Экспортёр дополнительно проверен на пустой локальной базе: 0 статей и 4 редакционных редиректа; файл создан с правами `0600`, затем dry-run корректно выдал отсутствующие источники как blockers. Production-snapshot этим не имитируется.

В предложениях сохранены дословные поисковые цитаты и связанные с ними частотности: коммерческая ссылка из цитаты снимается, а тематическая отсылка даётся отдельной фразой. Частотности не приписываются новым формулировкам анкоров.
