# SEO URL и sitemap — 1 ноября 2026 года

Изменения подготовлены в PR к `main`, без слияния и deployment. Production и его данные не изменялись. Раздел «SEO-страницы» сейчас покрывает статические страницы и лендинги, но не статьи; поэтому временный noindex Instagram задан в коде и вступит в силу после будущей выкладки PR.

## Проверка рабочего сайта через браузер

- `/blog/qr-kod-dlya-wifi-gostyam`: один canonical и один og:url, оба уже равны `https://qr-s.ru/blog/qr-kod-dlya-wifi-gostyam`. Двойной слэш в текущем ответе не воспроизводится.
- `/sitemap.xml`: **77 URL страниц**, включая **34 страницы/лендинга и 43 статьи**. `image:loc` не учитывались как отдельные страницы. `/qr-dlya-max` присутствует.
- `/robots.txt`: `Sitemap: https://qr-s.ru/sitemap.xml` уже присутствует.
- `/blog/qr-kod-na-instagram`: пока остаётся в опубликованном sitemap; noindex ещё не применён на production.

## Результат PR

На составе опубликованного сайта, зафиксированном браузером при проверке, новый генератор возвращает **76 URL: 34 страницы и 42 статьи**. Единственный исключённый URL — `/blog/qr-kod-na-instagram`. Остальные 76 прежних URL сохранены. Состав динамический: последующие публикации и настройки noindex изменяют число записей автоматически.

- Единый `publicSiteUrl` нормализует origin и повторные слэши пути. Query и fragment, в том числе вложенные URL, не переписываются. Внешний host нельзя подставить через ведущий `//`.
- Canonical и og:url используют один адрес во всех лендингах, статических SEO-шаблонах и блоге. Исправлен также og:url статических страниц, ранее наследовавших URL главной страницы.
- Источник лендингов — полный каталог, используемый разделом «SEO-страницы», с текущими noindex и датами правок. Статьи выбираются из БД при каждом запросе sitemap. Черновики, редакционные редиректы, закрытые страницы и Instagram исключены; изображения сохранены; URL не дублируются.
- При недоступности БД sitemap возвращает ошибку для повторного обхода, вместо HTTP 200 с исчезнувшими статьями или потерянными настройками noindex.
- Для статических страниц lastmod — максимум даты версии исходников и `updatedAt` SEO-правки. Версии исходников записаны в манифест с SHA-256 зависимостей шаблона; `pretest` и `prebuild` автоматически обновляют его в Git checkout. При неизменных исходниках дата сохраняется. В Docker без `.git` проверяются те же отпечатки, без GitHub API или дат времени деплоя. Изменённый исходник со старым манифестом останавливает сборку: нужно выполнить `npm run seo:source-dates` в checkout и включить манифест в коммит.
- Для статей lastmod опирается на `contentUpdatedAt` (для старых записей — `updatedAt`) и дату публикации; изменение счётчиков не двигает редакторскую дату у статей с `contentUpdatedAt`. Дата `/blog` учитывает новые и обновлённые индексируемые статьи.
- Robots-policy сохраняет пользовательские правила и дополнительные Sitemap, добавляя собственный `/sitemap.xml`, даже если его убрали из пользовательского текста robots.txt.
- Instagram сохраняет доступность страницы, self-canonical и `follow`; добавляется `noindex`, URL исключается из sitemap. Disallow не добавляется, чтобы поисковый робот мог прочитать noindex.

- 24 HTTP-интеграционные проверки на синтетической локальной PostgreSQL: успешно в dev и на production build. Проверены реальные HTML canonical/og:url для всех страниц каталога и блога, robots, sitemap, смена/очистка SEO-правок, история и конфликты параллельного редактирования.
