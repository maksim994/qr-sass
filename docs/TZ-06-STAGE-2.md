# ТЗ-06 · этап 2

## До изменений

Публикация определяется `publishedAt`; отдельного статуса, расписания, версий и секретного просмотра нет. Сохранения идут через два защищённых admin-route, с optimistic locking по `updatedAt`. Общий журнал `AdminAuditLog` содержит только изменения доступа, поэтому редакционные события вынесем в отдельный журнал со ссылкой из общего.

## Решение

- Добавочные таблицы версий, редакционных событий и хешей ссылок предпросмотра. Сохранение + версия + события атомарны. На первом изменении старой статьи сохраняется также исходная версия. Снимки содержат все редакционные поля, включая HTML/Markdown, встроенные изображения с alt, даты, флаги и статус; счётчики просмотров/лайков не откатываются.
- Nullable enum статуса: старые строки без переписывания читаются по `publishedAt`; новые — draft / scheduled / published. У scheduled `publishedAt = null`, поэтому предыдущий образ также не покажет их до публикации.
- Существующий notification-worker проверяет расписание каждые 4 секунды; отдельная итерация публикации не зависит от ошибок Telegram. Публикация проходит через общий transactional helper, создаёт версию и запись журнала, время первой публикации берётся из расписания. Ввод времени в админке явно МСК.
- Секретная ссылка из 32 случайных байтов, в БД только SHA-256; перевыпуск отзывает предыдущие ссылки, явный отзыв доступен в админке. Страница без кэша, noindex/nofollow в metadata и HTTP, без публичных счётчиков.
- История и сравнение двух версий, построчный diff тела, откат создаёт новую версию. Опубликованный ранее URL закреплён; необратимая конвертация Markdown→HTML при обычном редактировании закрыта, исторический откат восстанавливает исходный формат.
- Этапы 3–4 (API-ключи и REST API, редиректы, менеджер изображений) не реализуются в этом релизе. Журнал допускает их будущие события.

## Проверки и выпуск

### Реализовано

- `blog-versions.ts` — полный редакционный снимок и запись событий; `blog-workflow.ts` — атомарные сохранение/восстановление/удаление и выдача/отзыв предпросмотра. Конфликты `updatedAt` возвращают 409, в том числе при восстановлении; монотонная дата защищает от двух сохранений в одну миллисекунду. Ошибка сохранения не оставляет отдельную версию.
- Первая правка старой статьи сохраняет исходное состояние №0, затем новое №1. Автор исходного состояния честно обозначен «До включения истории»; последующие версии содержат реального администратора или имя источника API. Счётчики, ID и владелец статьи не восстанавливаются. Первая публикация и закреплённый публичный URL сохраняются; восстановление содержимого считается новой редакционной правкой. Точная копия legacyHtml остаётся доступной.
- `/admin/blog/<id>/versions`: выбор двух версий, построчный diff со знаками +/−, сравнение остальных полей, однокнопочное восстановление. Рядом с кнопкой показаны возвращаемый статус и время расписания. При восстановлении уже прошедшего расписания worker обработает его в ближайшем цикле.
- `/admin/blog/history`: фильтры по статье, автору и действию; ссылка есть из блога и общего журнала доступа. Записи сохраняются при удалении статьи/пользователя. Для будущих этапов предусмотрены типы событий API-токенов и редиректов; самих этих функций в этапе 2 нет.
- draft / scheduled / published; nullable-статус старых строк читается без backfill. SQL CHECK сохраняет совместимость публичных запросов: у draft/scheduled всегда `publishedAt = null`. Поэтому они исключены из списка, главной, sitemap, рекомендаций и публичных счётчиков. RSS в проекте отсутствует.
- `/preview/<token>`: 256 бит случайности, SHA-256 в БД, перевыпуск отзывает прежние ссылки, отдельный отзыв. Ссылка показывается один раз. HTTP и meta noindex/nofollow, private/no-store, no-referrer. На preview отключены глобальный custom head и компоненты аналитики, чтобы секретный URL не отправлялся счётчикам. Предпросмотр показывает последнее сохранение, не несохранённый текст формы.
- `blog-scheduler.ts`: каждые 4 секунды в действующем notification-worker; ошибки Telegram не останавливают проверку расписания. Несколько worker не публикуют одну запись дважды. Время первой публикации — запланированный момент, а не момент выполнения цикла. МСК преобразуется в UTC независимо от часового пояса браузера; повторная публикация сохраняет самую первую дату. IndexNow ограничен таймаутом 5 секунд на endpoint.
