### Метрика, раздел 8.1

Счётчик на production — 106988416, настройки не менялись. `CookieBanner` создаёт очередь ym и инициализирует счётчик только после accepted; накопленные без согласия действия не воспроизводятся.

| Цель | Причина / изменение | Реализация |
|---|---|---|
| registration_completed | Email вызывал цель до редиректа/готовности счётчика. Теперь email и Яндекс оставляют однократную server receipt, получение и method — после перехода/готовности счётчика | api/auth/register, api/analytics/registration, registration-goal |
| qr_created | Сохранение уже отправлялось; публичная статика не отправляла. Создание в генераторе фиксируется при первом успешном скачивании данного содержимого | create-qr-client, home-quick-start |
| qr_downloaded | Публичный генератор отправлял static_qr_downloaded. Идентификатор исправлен; format/frame/where через общий allowlist | product-analytics, tracked-download-link, qr-wizard-shared |
| first_external_open | Серверная FunnelEvent не является reachGoal. Выбрана разрешённая ТЗ отложенная цель при следующем согласившемся визите владельца; atomic receipt по QR предотвращает дубли | api/analytics/owner-open, owner-open-goals |
| checkout_started | Существующий вызов сохранён; planId нормализован в plan | billing-client, product-analytics |
| payment_succeeded | Одного server event недостаточно; добавлена цель по подтверждённому нетестовому SUCCEEDED с начисленной подпиской, только по возврату в кабинет. Claim `PENDING → BROWSER_SENT` исключает повторы и конкуренцию с offline worker | api/analytics/payment, confirmed-payment-goal |
| dynamic_enabled | Было dynamic_qr_created | create-qr-client, product-analytics |
| pricing_view | Было pricing_viewed; теперь секция по IntersectionObserver и отдельная страница | pricing-goal, page-goal |
| trial_started | Существующий вызов сохранён после успешного ответа | billing-client |
| upgrade_prompt_click | Добавлены place/plan для лимитов, статической статистики, команды/API, billing и after_download | upgrade-prompt, upgrade-link, billing-client, home-quick-start |

Все параметры проходят allowlist: type, dynamic, where, format, frame, plan, place, method, revenue, currency. Email, телефон, имя, URL, содержимое QR и пароль Wi-Fi отбрасываются. first_external_open не передаёт scanner ClientID/IP/UA: конверсия относится к последующему визиту владельца, не ко времени сканирования. Новая доставка применяется к открытиям с 18 октября, прежняя статистика не переписывается. Если владелец не возвращается или не даёт согласие, цель не отправляется. Это ограничение выбранного варианта.

payment_succeeded относится к подтверждённым оплатам за последние сутки. Серверная receipt гарантирует однократный вызов приложением, но блокировщик или потеря сети после claim могут помешать доставке Яндексу; transport exactly-once не обещается. Offline worker продолжает свой согласованный путь для платежей, не забранных браузером. Никакие реальные или прежние платежи для теста не создавались и не начислялись.

Владелец создаёт **4 новые JavaScript-цели**, условие «идентификатор совпадает»: `dynamic_enabled`, `pricing_view`, `trial_started`, `upgrade_prompt_click`. Шесть старых не переименовывать. Фильтр «Не учитывать мои визиты» меняет сам владелец.
