# ТЗ-02: первый экран qr-s.ru

## До правок — раздел 0

Production c07fbc7, исходная ветка HEAD 597dea6. Hero: `src/components/landing/home-experience.tsx` / `home-experience.module.css`; генератор и обработчики: `home-quick-start.tsx` / `src/app/home.module.css`. Существующие стили после нескольких overrides сжимают генератор в правой колонке; типы прокручиваются горизонтально, превью 172–180 px вместе с полями и скачиванием.

`download()` вызывает `downloadStaticQr()` (PNG/SVG), затем qr_created один раз на содержимое и qr_downloaded один раз на скачивание через markOnboardingDownloaded. `continueDynamic()` пишет прежний qr-draft и использует createQrContinuePath и /register?next=. `archive()` пишет static-qr-draft и отправляет в прежний /dashboard/create. Выбор типа и «Ещё типы» — local state; PDF/MENU/SOCIAL_LINKS отправляют в кабинет. Сервер страницы разбирает ?static= и url=; якорь #create-qr сохраняется.

Рамки уже реализованы: FrameControls, HomeQrPreview и `qr-frame.ts::withQrFrame`; экспорт использует тот же withQrFrame. Кириллические подписи — контуры. Превью и скачивание включают quiet zone. Бесплатный публичный генератор поддерживает только PNG/SVG, поэтому бесплатной ссылки PDF не будет.

Цели: qr_created/qr_downloaded — download; upgrade_prompt_click(place=after_download) — существующий CTA; dynamic_enabled — подтверждённое создание в кабинете, новый выбор динамики на hero по явному ТЗ-02 также вызывает существующий идентификатор с type=URL,dynamic=true,where=home. Все вызовы через trackGoal с прежней проверкой согласия/allowlist. Липкая кнопка будет вызывать тот же download, без второго слоя аналитики.

Скриншоты до: `outputs/hero-2026-10-18/before-{d,m}-{first,filled}.png`, точные viewport 1366×900 и 390×844. Сняты в отдельном тестовом браузере, без аналитики. Production данные не редактировались.

## Направление

Один H1 по центру, единый широкий генератор 1200 px. Путь: поле → шесть плиток → тип кода → крупный QR → синее скачивание. Подробности архивирования и печати переходят в FAQ; текущий Manrope, синий бренд, токены и темы сохраняются. Мобильный порядок совпадает с чтением и фокусом; длинные формы растут естественно. Блок сценариев меняет только внешний отступ.

## Реализация и проверка кандидата

Изменённые файлы: `src/components/landing/{home-quick-start.tsx,home-generator.module.css,home-experience.tsx,home-experience.module.css}`, `src/components/qr/frame-controls.tsx` (необязательные подписи только для hero), `src/components/cookie-banner.tsx` (только измерение высоты для отступа), `src/app/globals.css` (cookie touch targets 44 px), `src/app/page.tsx` (FAQ) и этот отчёт. Нет изменений Prisma, маршрутов QR, платежей или фоновых обработчиков.

- 193 unit-теста, TypeScript, ESLint и production build проходят. Механический layout-скан impeccable: пустой список находок.
- 1366×900: карточка 1200 px, bottom 896 px; кнопка PNG 52 px, bottom 789 px. QR 265 px внутри рамки 340 px. 390×844: QR 225 px внутри рамки 288 px, кнопка заканчивается на 1243 px (<1270). Размер образца и результата одинаков, перепрыгивания при вводе нет.
- Ширины 360/390/768/1024/1366/1440: горизонтальной прокрутки нет. На мобильных среди видимых кнопок генератора нет targets меньше 44×44. Поле — 52 px и 16 px шрифт. Прямой `?static=WIFI` выбран правильно. Enter/Space используют нативные button/radio/details, focus-visible задан.
- Ссылка в подзаголовке переключает динамический режим. Переход ведёт в `/register?next=%2Fdashboard%2Fcreate%2Furl%3Fkind%3DDYNAMIC%26url%3Dhttps%253A%252F%252Fexample.com`, статическое сохранение — в `/register?next=%2Fdashboard%2Fcreate`.
- Липкая PNG-кнопка появляется после ухода исходной области над viewport, вызывает общий `download`. При открытом cookie-баннере 89.8 px её нижний край 738.2 px, верх баннера 754.2 px: перекрытия нет. Измерение ResizeObserver не меняет согласие и его обработчики.
- Настоящие скачанные PNG через липкую кнопку и SVG после выбора «Оставьте отзыв» независимым jsQR декодируются в исходный `https://example.com`; PNG 1200×1200, SVG также растрирован в 1200×1200. Файлы: `download-sticky.png`, `download-frame.svg`. Физическая камера не заявляется.
- Снимки after-d-first/filled, after-m-first/filled/sticky, after-d-dark, after-m-dark находятся рядом с before в `outputs/hero-2026-10-18`; outputs исключены из Git. Сценарии с телефоном не редактировались, изменён только внешний отступ 72/48 px.
- Исходный мобильный Lighthouse через настоящий PageSpeed Insights: Performance 90, LCP 3.3 s, CLS 0, TBT 20 ms. Отчёт: https://pagespeed.web.dev/analysis/https-qr-s-ru/dkpnwmv53a?form_factor=mobile, текст сохранён в pagespeed-before.txt. Итоговый замер после deploy фиксируется отдельно.
