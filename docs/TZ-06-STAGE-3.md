## До реализации

Сейчас редактор, история и расписание работают через административную сессию. Ключи рабочих пространств предназначены для QR и не дают доступа к статьям. Общего API статей нет. В production остался один служебный черновик этапа 2; владелец разрешил удалить именно его с сохранением истории.

Добавляем отдельные именованные ключи статей, однократную выдачу, хранение только salted SHA-256, отзыв и последнее использование. Лимит — 60 запросов за минуту на ключ, единый в PostgreSQL для всех экземпляров приложения. Доступ — только Bearer, без наследования административной сессии или QR-ключей. Управление ключами — только администратор с существующей защитой CSRF.

API: список с пагинацией/фильтрами, чтение всех редакционных полей, создание исключительно черновика и изменение текста/метаданных, включая опубликованные статьи. PATCH требует числовой `version`; сравнение и запись происходят в одной транзакции. Публикация, снятие, расписание, удаление и смена опубликованного slug запрещены. Сохраняем существующий общий редактор, санитизацию, версии и журнал с автором `API: <имя ключа>`.

OpenAPI 3.1 будет в `openapi.yaml` и публичной схеме `/api/v1/openapi.json` без пользовательских данных. Документация содержит примеры curl. Миграция только добавляет таблицу токенов и nullable alt обложки. Существующие статьи и QR не переписываем.

Настоящий ключ не попадает в чат, отчёт, Git или логи. Однократная выдача — в защищённой административной форме. Перед передачей боту нужен подтверждённый защищённый канал; обычное сообщение не используется.

## Выдача ключа и приёмка

В этом чате нет отдельного инструмента защищённой отправки секретов. Безопасная однократная выдача реализована в [админке](https://qr-s.ru/admin/blog/tokens), по HTTPS с административной сессией и CSRF. Ключ хранится только salted SHA-256, повторно получить его нельзя. После создания владелец переносит его в защищённое поле секретов бота. Ключи не отправляются обычным сообщением или письмом. Сейчас активного боевого ключа нет — выдача ждёт запроса владельца/готового защищённого канала.
