# ТЗ-07: API изображений и предпросмотра

## Контракт

- `POST /api/v1/images`: самостоятельная загрузка file/alt, kind=content по умолчанию. Общие проверки и WebP 480/960/1600 без увеличения. Ответ url/variants/srcset/figure. Журнал image_upload с API-автором; статья/версия не создаются. После S3 повторно проверяется отзыв ключа, при неуспехе удаляются только новые объекты.
- `PATCH /api/v1/articles/{id}/images`: version/url/alt, необязательные newUrl/minorEdit/comment. Старые alt-only запросы совместимы. URL совпадает точно, все совпавшие картинки/обложка обновляются. HTML не конвертируется; меняются только нужные атрибуты по исходным смещениям. Сохраняются остальной HTML, якоря, format/legacyHtml, время чтения и даты публикации. Для загруженного файла заменяются srcset/размеры; для внешнего URL старые responsive-атрибуты удаляются. Кодовые примеры пропускаются.
- `minorEdit=true` сохраняет редакционный contentUpdatedAt; служебный updatedAt изменяется при записи версии. Без флага существенная замена обновляет редакционную дату. No-op не меняет дату.
- CAS проверка версии внутри транзакции, 409 при конфликте. Версия и журнал с API-автором. Публикация/расписание/удаление остаются запрещены.
- `POST /api/v1/articles/{id}/preview`: JSON {} использует сохранённый текст, content/format/faq задают временные поля. Возвращает html/items тем же рендерером сайта. Не пишет статью, даты, версии, события или preview-токены. Авторизация учитывает использование ключа.
- OpenAPI 1.2.0, curl-примеры в ARTICLE-API.md. Новая схема БД/миграция не требуются.
