До завершения демо переход на return URL оставил заказ PENDING. После выбора успешного исхода в симуляторе Robokassa настоящий внешний callback перевёл заказ в SUCCEEDED; до этого собственное уведомление об успехе не отправлялось. Затем проверены повтор подписанного callback (HTTP 200, точный `OK` + InvId), неверная подпись (403), подписанная неправильная сумма (403). Подтверждение теста записано один раз, подписка неизменна, события реальной оплаты/выручки не созданы. Браузер вернулся в кабинет с сообщением «Тестовая оплата подтверждена».

## Откат и следующий этап

ЮKassa уже остаётся основным checkout. Перед боевым запуском Robokassa владелец должен приватно заполнить основные пароли №1/№2, затем отдельно включить `BILLING_PROVIDER=robokassa`, `ROBOKASSA_TEST_MODE=false` и проверить реальную оплату/чек/возврат.

При откате приложения сохранить текущий backup и образ, выбрать прежний commit/сохранённый образ в Coolify и выполнить обычный redeploy с прежними production-томами. Добавочное поле provider удалять не требуется. Старый образ совместим с обновлённой схемой, что проверено на восстановленной копии. Не восстанавливать старую БД поверх актуальной для обычного отката приложения. Старый образ не содержит callback Robokassa: пока есть ожидающие заказы Robokassa, их обработчик и соответствующие ключи необходимо сохранить.
