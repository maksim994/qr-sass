## Что сделано

1. **Один черновик изменений на опубликованную статью.** Добавлена отдельная таблица `BlogPendingRevision`, уникальная по `postId`. Хранятся редакционные поля, снимок подготовленного текста и дата исходной живой версии. Создание/изменение черновика не трогает статью, её даты, счётчики, историю версий и sitemap.
2. **API с существующими редакционными Bearer-ключами.** `PUT/GET/DELETE /api/v1/articles/{id}/revision`, `POST /api/v1/articles/{id}/revision/preview`. Предпросмотр возвращает абсолютный `url` и относительный `path`. Публикации через редакционный API нет. OpenAPI обновлён до **1.4.0**, обе копии генерируются одним скриптом.
3. **Админка.** Пометка «Есть черновик изменений» в списке и блок на странице редактирования: построчный diff с живой версией, секретный предпросмотр, «Опубликовать изменения», «Отменить черновик». Публикация доступна только администратору с cookie-сессией. При публикации редактор обновляется новым живым текстом.
4. **История и безопасность одновременных правок.** Публикация атомарно обновляет статью, добавляет версию и удаляет черновик. Откат использует существующую историю. Slug, URL, первая публикация, ID и счётчики сохраняются; `contentUpdatedAt` и динамический sitemap обновляются. Нельзя опубликовать черновик, если изменились живая версия или просмотренный черновик. Повторный клик не создаёт вторую версию.
5. **Секретные ссылки.** Токен хранится только в виде SHA-256. Предпросмотр показывает сохранённый снимок черновика, а не текущую живую статью; исключён из индексации и кеширования. Ротация ссылок черновика независима от ссылок живой статьи. Публикация/отмена черновика делает его ссылки недействительными (404).
6. **Блог.** Большая карточка удалена. Все 9 статей, включая первую, находятся в общей сетке с одинаковыми размерами карточек. Фильтры и пагинация сохранены. Отступ перед пагинацией — **48 px** на десктопе, **32 px** до 640 px; до футера измерено **96 / 48 px** соответственно.
7. **Главная.** Тёмный блок «Есть идея?» получает собственные светлые foreground-токены. Заголовок и тексты больше не наследуют тёмный цвет из оболочки главной. Палитра одинакова в светлой и тёмной теме. Компонент используется на главной; других мест использования в проекте нет.

## Контракт API

Ключ `QRS_ARTICLES_API_TOKEN` — переменная клиента с уже выданным ключом из `/admin/blog/tokens`. Нового серверного секрета не требуется. Авторизация, лимит 60 запросов/мин и формат ответов `{ok,data}` сохранены.

Пример подготовки правки:

```sh
curl -X PUT "https://qr-s.ru/api/v1/articles/$ARTICLE_ID/revision" \
  -H "Authorization: Bearer $QRS_ARTICLES_API_TOKEN" \
  -H 'Content-Type: application/json' \
  --data '{"title":"Новый заголовок","content":"## Новый текст\n\nТекст статьи."}'

curl -X POST "https://qr-s.ru/api/v1/articles/$ARTICLE_ID/revision/preview" \
  -H "Authorization: Bearer $QRS_ARTICLES_API_TOKEN"
```

Поддерживаются редакционные поля PATCH, включая все перечисленные в ТЗ и `format` / `confirmConversion` для существующих HTML-статей. `slug`, публикационные поля, счётчики, даты и `minorEdit` запрещены. Переданные поля объединяются с прежним черновиком; остальные сохраняются. Необязательный `version` проверяет номер живой истории. Для HTML сохраняются прежние ограничения: изменение тела требует явной конвертации в Markdown, оригинал HTML сохраняется для отката.

Если живая статья изменилась, PUT и публикация возвращают 409. Сохраните нужный текст, отмените черновик и создайте новый по актуальной статье. Отмена доступна и для устаревшего черновика. При отсутствии черновика GET/DELETE/preview возвращают 404. POST на `/api/v1/articles/{id}/revision` не поддерживается (405).

## Как проверить вручную

1. На тестовом стенде применить миграцию `20261021090000_blog_pending_revision`, сгенерировать Prisma Client и собрать приложение. Использовать опубликованную тестовую статью и действующий редакционный ключ.
2. Через PUT создать черновик с изменёнными title/content/FAQ. Открыть живую страницу и sitemap: старые текст и дата. Убедиться, что появилась только пометка в админке, без новой статьи `-v2`.
3. POST preview: открыть `data.url` в приватном окне без входа — новый текст. На странице редактирования раскрыть «Сравнить с живой версией» — видны удалённые и добавленные строки.
4. Нажать «Опубликовать изменения». На прежнем URL новый текст, первая публикация сохранена, в истории новая версия. Восстановить предыдущую версию — возвращается старый текст. Секретная ссылка опубликованного черновика возвращает 404.
5. Создать ещё один черновик и отменить его — живая статья и история не меняются. Проверить блокировку публикации после параллельной живой правки или изменения черновика из другой вкладки/API.
6. В Chrome и Safari на 1440 и 375 px проверить главную в обеих темах, `/blog`, выбранную рубрику и страницу 2. Все статьи обычными карточками, между сеткой и пагинацией 48/32 px, текст тёмного CTA читается.
