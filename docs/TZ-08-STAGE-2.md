## 2.0. До правок и выбранная доставка

Основа — принятый этап 1 (`62f717f`, production pin `ab0880c`). Ветка `codex/tz08-blog-media`.

Загрузчик `storeBlogImage` создаёт WebP 480/960/1600 в прежнем S3, ключи `qr/blog/covers|content/<unique-id>-<width>.webp`. `uploadFile` возвращал адрес S3, он попадал в BlogImage, url/variants/srcset/figure API, обложки и content статей. Legacy HTML и Markdown рендерятся и санитайзятся на сервере; редактирование исходников отдельно от публичного рендера. og:image и JSON-LD использовали coverImageUrl, sitemap содержал URL/lastmod, но не изображения. robots настраивается администратором.

Выбран `/media/blog/...` на прежнем домене через Next.js и существующий SDK в `s3.ts`. Стоимость дополнительных сервисов — **0 ₽**, без регистрации, DNS и TLS-настроек. Плюс: единый адрес и готовые инфраструктура/HTTPS; минус: первый запрос изображения проходит через приложение и S3. Ограниченный LRU-кеш процесса (64 MiB/128 записей), объединение одновременных чтений и immutable HTTP-кеш уменьшают повторную нагрузку. Поддомен потребовал бы дополнительной настройки DNS/TLS/CDN и не обеспечивал бы адрес qr-s.ru/media.

## Реализация

- Публичный маршрут разрешает только covers/content и WebP/PNG/JPEG/GIF в `qr/blog/`. Полный whitelist имени, без вложенных путей, произвольного upstream и доступа к workspace-файлам. Отдаёт байты, без редиректа и cookie; MIME, Content-Length, ETag, Last-Modified, HEAD, If-None-Match/If-Modified-Since → 304. Промах — 404; временная ошибка — 502 без внутренних адресов/текста SDK.
- Новые загрузки через три прежних API возвращают публичные url/variants/srcset/figure. Размеры и S3-ключи сохранены. Другие типы S3-загрузок не меняют адреса.
- При рендере меняются только image src/srcset, обложки, og:image/twitter:image и JSON-LD image. Источник content/coverImageUrl/legacyHtml в БД не переписывается. JSON-LD BlogPosting.image — ImageObject с реальными размерами (BlogImage либо измерение кешированных байтов S3).
- Sitemap получает image namespace/loc через штатную поддержку Next MetadataRoute.Sitemap; lastmod вычисляется прежним способом. robots явно разрешает /media/ в группах агентов.
- API замены/удаления узнаёт эквивалентные S3 и media URL, сохраняя точечное изменение исходника и правила этапа 1.

Миграция URL в БД не выполняется: в ТЗ она разрешена только отдельной командой Максима. Старые S3-файлы не перемещаются и не удаляются.

## Уточнение фактических данных

Production содержит 44 записи, но прежний sitemap включает **40 индексируемых статей**: четыре устаревших адреса перенаправляются и исключаются существующим фильтром. Добавление изображений сохраняет эти 40 URL; не возвращает дубли-редиректы в индекс. Проверка дат охватывает все 44 записи. Аналогично в базе один Markdown, а не два; второй случай Markdown покрывается синтетической HTTP-приёмкой, без конвертации существующих статей.

В общем layout присутствует отдельно настроенный favicon `s3.mvmolkov.ru/qr/site/...`. Он находится вне разрешённого префикса `qr/blog/`, поэтому остаётся на прежнем адресе. Проверка отсутствия S3 в HTML относится к изображениям блога и их метаданным; favicon и приватные/пользовательские ключи не открываются через `/media/blog/`.
