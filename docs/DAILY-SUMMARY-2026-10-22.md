# Ежедневная сводка: расследование 22 октября 2026

## Причина

Планировщик сработал правильно: 22.10 в 09:00:55 МСК Beget принял сводку, но в 09:00:58 вернул её с `Action: failed`, `Status: 5.0.0`: `host mx.yandex.ru [77.88.21.249]: retry timeout exceeded`. Приложение фиксировало только приём SMTP и не проверяло последующие возвраты, поэтому запись осталась `SENT`, алерт не возник.

Это подтверждённый отказ доставки между Beget и Яндексом; конкретная причина тайм-аута на стороне провайдеров из доступного возврата не установлена. Ошибка часового пояса и пропуск пустого дня исключены. Настройки провайдеров и DNS не менялись.

## Свидетельства до правок

- В 05:00–10:00 МСК журналы действующего email-worker не содержат ошибок исполнения или SMTP, только предупреждение Node о типе модуля.
- `EmailControl.enabledSince`: 21.10.2026 18:00:20.872 МСК; heartbeat и watermark актуальны. Отдельный сервис `email-worker` в Compose работает, независимый monitor имеет `Result=success`. Для сводки не требуется cron Coolify: проверка внутри worker раз в минуту с явным `Europe/Moscow`.
- `digest:2026-10-22`: создан 09:00:55.344, SMTP принят 09:00:55.633 МСК, `SENT`, attempts=1, errorCode=null. Получатель проверен на соответствие адресу владельца.
- В ящике отправителя найден один возврат за 22 октября. Исходный Message-ID в нём точно совпал с ID этой сводки; дата возврата 09:00:58 МСК. Секреты и полные письма не сохранялись в отчёт.
- Production уже содержит последующий API-релиз `c2d4b0b`; новая ветка основана на локальной `4645177`, включающей этот код и отчёты. Работа с устаревшим `a4d6b13` не перезапишет последующий выпуск.

## Подготовленные изменения

- Общий построитель сводки для планировщика и ручного запуска; уникальные ключи сохраняют защиту от дублей. Дата в теме, нули и строка «За сутки регистраций и оплат не было» при пустом дне.
- Ручная команда `npm run email:digest -- --date=YYYY-MM-DD`: предварительный просмотр. `--send` ставит тестовую сводку только владельцу через штатную очередь. Один тест на дату, без персональных данных и побочных обработок чужой очереди.
- Сохранены 5 попыток доставки с задержками и алерт при окончательном отказе; добавлены безопасные журналы кодов ошибок. Ошибка scheduler не блокирует доставку готовых писем. Сводка не отменяется уже через сутки, общая очистка содержимого через 7 дней остаётся.
- Контроль отсутствия принятой сводки после 09:10 МСК и проверка последующих DSN-возвратов через IMAP в независимом мониторе. Точный исходный Message-ID исключает чужие письма. При найденном отказе — безопасная запись в журнал и уведомление; автоматические повторы постоянного отказа не запускаются.
