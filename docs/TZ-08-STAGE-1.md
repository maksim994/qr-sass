# ТЗ-08 · этап 1 · удаление изображения

## 1.0. Устройство до правок и решение

Основа: `8691c3a` (ТЗ-07), рабочая ветка `codex/tz08-image-remove`.

- PATCH `/api/v1/articles/{id}/images` заменяет точные src/Markdown URL и alt, включая обложку. JSDOM предоставляет позиции атрибутов; остальная HTML-строка не сериализуется заново.
- `persistArticle` в транзакции проверяет активность токена, последнюю редакционную версию, затем обновляет статью по CAS `id + updatedAt`. Конкурирующая запись получает 409. `recordSave` хранит исходный снимок №0 при первом изменении и новую полную версию с автором.
- Журнал связывается с ревизией. Админский restore восстанавливает исходный content из snapshot; legacyHtml удерживается отдельно. Обычный restore меняет редакционную дату — прежнее поведение.
- Preview API и админский `/api/admin/blog/preview` используют общий серверный renderer с санитайзингом. Preview не сохраняет статью.

Выбран существующий PATCH с `{version,url,remove:true,all?,minorEdit?,comment?}`. Строгая union-схема отделяет удаление от замены и не меняет прежние запросы. Авторизация, лимит 60/мин и CSRF-модель остаются прежними. Новый endpoint и права не нужны.

## Реализация

Чистая функция вырезает диапазоны исходной строки: figure с figcaption, если img — единственное медиа, иначе img и пустые a/p. Точное сопоставление учитывает srcset. Markdown inline images и raw HTML поддерживаются; примеры кода/комментарии/атрибуты исключены. Сначала подсчитываются изображения, при повторах возвращается 409 с `details.count`, `all:true` разрешает удалить все. Отдельные проверки: 404 для отсутствующего URL, 400 для URL обложки.

Удаление проходит прежний контроль разрешённой точечной HTML-правки, CAS и snapshot writer. Создаётся отдельное событие `image_remove` с URL, комментарием и автором API. S3 не вызывается, legacyHtml не меняется. Оба preview endpoint используют ту же проверку и возвращают изменённый исходник только для запрошенного удаления. Необязательная кнопка в форме не добавлена.

OpenAPI 1.3.0 формируется общим генератором для `openapi.yaml` и публичной JSON-схемы. Примеры и ошибки описаны в ARTICLE-API.md.

Коммиты реализации: `0b67ecb`, `ab0880c` (приёмка на копии реальной статьи).
