# Архивные условия и «Для своих»

Реализация подготовлена 19.09.2026. На production не применялась.

## Сохранение старых условий

Миграция `20260919160000_preserve_workspace_terms` сохраняет в каждом существующем workspace снимок текущего тарифа и FREE-условий из PlanOverride/defaults. QR, Workspace.plan, даты подписок и платежи не меняются. Новые workspace получают `accessMode=standard`, прежние — `archive`. Снимок версии 1 не редактируется пользовательским API. Повреждённый снимок вызывает ошибку, а не незаметную подмену прав публичными значениями.

Архивный BUSINESS без подписки сохраняет бессрочный доступ. Подписки с датой сохраняют эту дату: истёкший период не становится бессрочным. После окончания периода остаются FREE-возможности и работа старых QR; архивный платный тариф можно продлить по сохранённой цене. Переход на публичный тариф требует подтверждения и применяется после успешной оплаты. Пробный период на публичных условиях также требует подтверждения замены архива.

## Назначение «Для своих»

**Админка → Клиенты → кабинет → Изменить доступ → Для своих.**

Скрытый бесплатный бессрочный тариф: все имеющиеся функции, QR и участники без тарифных лимитов, API и экспорт. Общие технические ограничения файлов, частоты запросов и размера одного массового задания остаются. Ручное назначение требует администратора и причины, записывается в журнал и не создаёт платёж. Никого автоматически на «Для своих» не переводим.

Архивные условия можно восстановить в той же форме, если у кабинета сохранён снимок; срок сам по себе не продлевается. Исторические записи подписки и платежей сохраняются.

Запоздалый платёж не заменяет «Для своих» или бессрочный архивный доступ: сохраняется факт оплаты и событие `payment.access_preserved` для ручного разбора. Автоматического возврата средств нет. Создание новых платежей в таком кабинете заблокировано.

## Переход JWT без массового выхода

В production пока ключ длиной 31 символ, новый runtime требует минимум 32. При запуске новой версии нужен новый сильный `JWT_SECRET`; прежний ключ передаётся только как `JWT_PREVIOUS_SECRET`, точный момент переключения UTC — как `JWT_ROTATED_AT`. Настройки должны применяться согласованно со стартом новой версии.

Новые сессии подписываются только новым ключом. Старые принимаются до исходного exp, максимум семь суток от переключения. Старый ключ не принимается для сессий с iat после переключения или сроком более семи суток. Через семь дней удалить обе временные переменные. Основной ключ не менять при обычных последующих релизах. Реальные ключи в ходе разработки не менялись.

Для отката на старый образ нужны также старые настройки ключа; пользователи с новыми сессиями могут потребовать повторный вход. После назначения специальных условий старый код не умеет интерпретировать их полностью: откат проверять отдельно, одного совпадения SQL-схемы недостаточно.
